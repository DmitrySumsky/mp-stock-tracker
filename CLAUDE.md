## Что это за проект

**MP Stock Tracker** — Google Apps Script, который работает внутри Google Sheets.
Цель проекта — полная автоматизация операционных и финансовых процессов бизнеса на маркетплейсах. Проект активно развивается: текущие модули — только начало, новые будут добавляться по мере роста задач.

Собран по стандарту **«Пульт»** (`57.mp-core/ПУЛЬТ.md`). Читай стандарт перед правкой:
в книге лежит только лоадер, логика — одним собранным файлом в этом репозитории.

Текущие модули (v3.5):

1. **Остатки маркетплейсов** — собирает остатки товаров с OZON и WB по всем кабинетам ИП через их API, записывает в отдельные листы, уведомляет в Telegram.
2. **Остатки МойСклад** — выгружает остатки со складов с себестоимостью и ценой продажи в лист «Остатки МС».
3. **Кредиты** — синхронизирует остатки задолженностей по кредитам из листа «Кредиты Import» в управленческий баланс.

Архитектура намеренно модульная — каждый новый модуль добавляется как отдельный файл, не затрагивая существующий код.

Владелец: **DmitrySumsky** (dmitriy.sumski@gmail.com).

### Как GAS выполняет файлы

Google Apps Script загружает все `.gs` файлы в **одном глобальном скоупе** — переменные и функции из одного файла видны во всех остальных. Нумерация `00_`…`99_` задаёт порядок загрузки (важно: константы из `00_constants.gs` должны быть доступны всем остальным).

### Центральный конфиг — лист «Панель управления»

Все токены и настройки хранятся **только в таблице**, не в коде:

| Ячейка | Содержимое |
|--------|------------|
| B2 | Telegram Bot Token |
| B3 | Chat ID(s), через `;` |
| B5 | API-токен МойСклад |
| Строки 9+ | Кабинеты маркетплейсов (MP, ИП, ключи, имя листа) |

Функции чтения: `loadTelegramConfig()`, `getMsToken_()`, `loadCabinets()` — в `02_config.gs`.

## Правила работы над проектом

### 1. Никаких токенов и credentials в коде

Все секреты читаются из таблицы через функции из `02_config.gs`. Если нужен новый токен — добавляй поле в `initPanel()` (`01_panel.gs`) и читалку в `02_config.gs`.

### 2. Один модуль — один файл

Новый независимый модуль = новый файл `NN_name.js` в `central/`. Нумерация задаёт порядок сборки. Не добавляй функции нового модуля в существующие файлы.

### 3. Константы только в `00_constants.gs`

Все `const` верхнего уровня — только в `00_constants.gs`. В остальных файлах локальные переменные внутри функций — ок.

### 4. Приватные функции с суффиксом `_`

Вспомогательные функции, не предназначенные для прямого вызова из меню — именуются с `_` на конце: `getMsToken_()`, `fetchMsPage_()`. Публичные (вызываемые из меню или триггеров) — без `_`.

### 5. Меню только в лоадере

`onOpen` — простой триггер, ему запрещён `UrlFetchApp`, поэтому меню живёт в
`loader/loader.gs`, а не в центральном коде. Пункты пронумерованы по порядку работы,
редкое — в подменю. 🔴 в этой книге нет: наружу она не пишет.

Новая функция центрального кода правки лоадера НЕ требует — `run_()` резолвит её по
имени. Лоадер трогается только ради новой КНОПКИ. Имена точек входа не переименовывать:
на них висят пункты меню и уже установленные триггеры.

### 6. Логирование через `writeLog()`

Все операции с данными логируются через `writeLog(mp, ip, status, details)` из `12_utils.gs`. Лог пишется в лист «Лог».

### 7. HTTP через `fetchWithRetry()`

Все внешние запросы — через `fetchWithRetry()` из `12_utils.js` (3 попытки,
экспоненциальный backoff). Исключение ровно одно и оно принципиальное: «🔌 Проверка
связи» (`13_pult.js`) ходит одним `UrlFetchApp.fetchAll` и БЕЗ ретраев — диагностика,
умеющая ждать, упирается в шестиминутный лимит и выглядит как «кнопка не работает».

### 8. Колонки листов — по заголовку, а не по номеру

Люди вставляют свои колонки, а раскладка листа меняется между версиями. Номер,
зашитый в код, однажды начинает указывать на соседнюю колонку и молча врёт (так
«Проверить низкие остатки» годами читала название товара как количество). Не нашли
колонку — молчим, а не выдаём цифры из чужой.

### 9. Инструкция обновляется тем же заходом

Изменил функциональность — обнови `panelHelp` в `13_pult.js` и версию в
`central/preamble.js`. Новая версия = новый блок сверху, старые не переписываются;
в блоке — причина, а не список правок.

## Деплой и рабочий цикл

### Обычная правка логики — только репозиторий

Книга тянет `central/build/central.js` из GitHub, поэтому правка логики до неё
доезжает БЕЗ похода в Apps Script:

```bash
node tools/build.js      # собрать (не прошли проверки — файла не будет)
node tests/run.js        # тесты на заглушках
node tools/deploy.js     # сухой прогон: что уедет в репозиторий и в книгу
node tools/deploy.js --push
```

Лоадер заливается **не** `clasp push`: clasp 3.3 не отправляет удаление файла, если
больше ничего не менялось, — отвечает «Script is already up to date», а файл остаётся
на сервере. `tools/deploy.js` кладёт состав проекта целиком через Apps Script API
(`PUT /v1/projects/{id}/content`) тем же аккаунтом, которым авторизован clasp.

Кэш кода в книге живёт 30 минут; пункты «⚙️ Обновить настройки таблицы» и
«ℹ️ Версия кода» сбрасывают его принудительно.

### Репозиторий публичный

`DmitrySumsky/mp-stock-tracker` открыт, поэтому лоадер тянет файл анонимно и книге
GitHub-токен не нужен (ячейка B6 панели — необязательный ускоритель со своей квотой).
Обратная сторона: сборка валится на скане утечек, и ключи в код попасть не могут.

## Добавление нового модуля (чеклист)

1. Создать `central/NN_name.js`
2. Если нужны константы — добавить в `central/00_constants.js`
3. Если нужно поле в панели — добавить в `initPanel()` (`01_panel.js`) и читалку в `02_config.js`
4. Публичную точку входа вписать в `ENTRY_POINTS` (`tools/build.js`) — сборка проверит, что она резолвится
5. Нужна КНОПКА — добавить пункт меню и обёртку в `loader/loader.gs` (иначе лоадер не трогать)
6. Обновить `panelHelp` (`13_pult.js`), версию в `central/preamble.js` и `CHANGELOG.md`
7. Дописать тесты в `tests/run.js`
8. `node tools/deploy.js --push`

## Известные ограничения GAS

- Максимальное время выполнения скрипта: **6 минут**. При большом числе кабинетов могут потребоваться батчи.
- `UrlFetchApp` делает запросы от имени Google — некоторые API это учитывают.
- Триггеры хранятся в Google-аккаунте пользователя, не в скрипте. При `removeTriggers()` удаляются ВСЕ триггеры проекта.
- GAS не поддерживает `import/export` — все файлы в одном глобальном скоупе.

## Используемые API

| Сервис | Endpoint | Аутентификация |
|--------|----------|----------------|
| OZON Seller | `/v2/analytics/stock_on_warehouses` (свободно/готовим/резерв) + `/v1/analytics/stocks` (в пути, возвраты, брак, кластер; SKU пачками по 100) + `/v4/product/info/stocks` (сбор номенклатуры) | `client-id` + `api-key` headers |
| WB Analytics (остатки) | `https://seller-analytics-api.wildberries.ru/api/v1/warehouse_remains` (async: заказ → status → download) | `Authorization` header, право **«Аналитика»** |
| МойСклад | `https://api.moysklad.ru/api/remap/1.2` | `Bearer` token |
| Telegram Bot | `https://api.telegram.org/bot{token}/sendMessage` | token в URL |
