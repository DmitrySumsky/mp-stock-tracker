# MP Stock Tracker v3.6

Автоматизация книги «Баланс Маркеты»: остатки OZON и Wildberries по всем кабинетам,
остатки МойСклада с себестоимостью, синхронизация кредитов в управленческий баланс,
уведомления в Telegram.

Собрана по стандарту **«Пульт»** (`57.mp-core/ПУЛЬТ.md`): в книге лежит только тонкий
**лоадер**, вся логика — одним файлом в этом репозитории. Правка логики = один пуш,
книга на новой версии со следующего клика. Лоадер трогается только ради нового пункта
меню: `run_()` резолвит функции центрального кода по имени.

```
loader/loader.gs            ← лежит в книге (меню, run_, HTML-диалоги, витрина скоупов)
loader/appsscript.json      ← манифест книги
central/*.js                ← модули логики (исходники)
central/preamble.js         ← версия и история версий: первая строка файла — строка версии
central/build/central.js    ← собранный центральный файл, его тянет лоадер
tests/run.js                ← тесты в Node на заглушках
tools/build.js              ← сборка со встроенными проверками
tools/deploy.js             ← сборка → тесты → репозиторий → книга
module.json                 ← контракт модуля
```

## Работа с кодом

```bash
node tools/build.js      # собрать central.js (не прошли проверки — файл не создаётся)
node tests/run.js        # тесты на заглушках
node tools/deploy.js     # сухой прогон: что уедет в репозиторий и в книгу
node tools/deploy.js --push
```

Сборка сама проверяет: синтаксис, резолв всех точек входа (ровно так, как это делает
`run_()` в книге), двойное объявление имён и утечки секретов. Не прошла — файла на
диске не остаётся, и деплой смотрит на код возврата, а не на вывод.

## Меню книги

Пункты пронумерованы в порядке работы — порядок кнопок и есть инструкция первого уровня.
Красных пунктов (🔴) нет: книга только ЧИТАЕТ у маркетплейсов и пишет в саму себя.

| Пункт | Что делает |
|---|---|
| 1️⃣ 🔄 Обновить остатки — все кабинеты | сбор по всем активным кабинетам OZON и WB |
| 2️⃣ 🏪 Обновить остатки МойСклад | отдельной кнопкой: МойСклад медленнее и рискует лимитом |
| 3️⃣ 💰 Остатки кабинетов в дебиторку… | долг WB и Ozon кабинету → строки «Остаток на балансе кабинета ВБ/ОЗОН» |
| 4️⃣ 💳 Кредиты в баланс… | из листа «Кредиты Import» в строки баланса |
| 📖 Как работать | инструкция из кода — не может отстать от версии |
| 📊 Что сейчас происходит | одно окно вместо трёх листов, называет ОДНО действие |
| 🔌 Проверка связи | все кабинеты одним `fetchAll`, без ретраев, диагноз словами |
| 🛠 Ручной режим ▸ | только OZON, только WB, выбор кабинетов, один кабинет, добавить кабинет |
| 📚 Диагностика ▸ | дашборд, экспорт CSV, низкие остатки, предпросмотр остатков кабинетов и кредитов |
| ⏰ Автозапуск ▸ | триггеры остатков и МойСклада |
| 🧹 Обслуживание ▸ | очистка старых данных, панель, миграция |
| ⚙️ Обновить настройки таблицы | досоздаёт новые колонки листов без боевого прогона |
| ℹ️ Версия кода | какая версия центрального файла сейчас в книге |

| Столбец | OZON | WB |
|---------|------|----|
| A | `OZON` | `WB` |
| B | название кабинета | название кабинета |

| D | API Key | — |
| E | — | Token |

валится на скане утечек.

## Остатки OZON: что откуда берётся

Источников три, и они дополняют друг друга:

| Ручка | Что даёт |
|---|---|
| `/v2/analytics/stock_on_warehouses` | свободно / готовим к продаже / резерв — только там, где товар физически лежит |
| `/v1/analytics/stocks` | в пути, возвраты, брак, ожидание документов, кластер склада |
| `/v2/posting/fbo/list` | «Доставляем покупателям» — уехало к покупателю, ещё не выкуплено |

Три места, где легко ошибиться (все три были боевыми ошибками, см. историю версий
в `central/preamble.js`):

- **имя склада** у двух ручек пишется по-разному (`Санкт_Петербург_РФЦ` и
  `САНКТ-ПЕТЕРБУРГ_РФЦ`) — ключ склейки выбрасывает всё, кроме букв и цифр;
- **`free_to_sell` уже содержит** товар «готовим к вывозу», который аналитика зовёт
  `return_to_seller` — складывать их нельзя, основа = `max(free, available + return_to_seller)`;
- **`awaiting_packaging` не входит** в «Доставляем покупателям»: этот товар ещё на
  складе и уже сидит в «Зарезервировано».

Итоговая колонка листа — **«Всего вверено OZON»**, её и берут запасы баланса.
«Заявлено к поставке» в неё не входит: этот товар ещё на нашем складе.

## Дебиторка: остатки кабинетов

| Строка баланса | Откуда |
|---|---|
| Остаток на балансе кабинета ВБ | `finance-api…/v1/account/balance`, поле `current` (нужна категория токена «Финансы») |
| Остаток на балансе кабинета ОЗОН | `/v1/finance/cash-flow-statement/list`, `end_balance_amount` самого свежего периода |
| Ожидаем поступление на РС от ВБ / ОЗОН | **ставит человек** — публичного метода нет ни у одной площадки |
| Дебиторская задолженность, итоги по ИП | формулы книги |

Осмысленна только сегодняшняя дата: истории по остатку кабинета площадки не отдают.
Кабинет с отказавшим ключом пропускается, ячейка остаётся как была — ноль в балансе
неотличим от факта.

## Листы книги

| Лист | Назначение |
|------|------------|
| Панель управления | токены, список кабинетов, статус последнего запуска |
| Дашборд | сводка по всем кабинетам |
| Лог | история запусков с причиной отказа словами |
| Остатки МС | остатки МойСклада |
| Остатки по кластерам … | данные OZON, история по дням (имя задаётся в столбце F) |
| Остатки ВБ … | данные WB, история по дням |
| Кредиты Import | источник данных по кредитам |

Листы остатков — **история**: каждый прогон дописывает свой день, повторный запуск в
тот же день переписывает только сегодняшний блок. Чистка — «🧹 Обслуживание → Очистка
старых данных».

## Адаптация модуля «Кредиты»

Константа `CREDIT_MAP` в `central/00_constants.js` связывает названия кредитов из листа
«Кредиты Import» со строками управленческого баланса. В репозитории она заполнена
примерами (`Субъект 1 Кредит A`) — до замены на реальные названия модуль ничего не
перенесёт. Ожидаемые заголовки листа-источника: `Основной долг`, `Кредит`, `Оплачено`.

- Google-аккаунт с доступом к Apps Script, `clasp` для заливки лоадера;
- Node 18+ для сборки и тестов;
