# Changelog

## [3.4.0] - 2026-08-05

### Fixed
- **ЛИСТ КОНЧИЛСЯ — ДЕНЬ НЕ ЗАГРУЗИЛСЯ: «Остатки ВБ ИП11» встал на 03.08.2026**
  (разбор владельца, 05.08.2026). Сетка листа была занята вся (7725 строк из 7725),
  снимок 03.08 влез частично (235 строк вместо ~390), а 04 и 05 августа не загрузились
  вообще. Ни ошибки в «Логе», ни уведомления в Telegram — записи просто не было.
  - `ensureCapacity_` (`12_utils.gs`): перед записью лист досоздаёт строки
    (`insertRowsAfter`) с запасом `SHEET_ROW_HEADROOM` = 2000, если снимок в сетку
    не помещается. Подключён во всех трёх местах, где данные дописываются снизу:
    `writeToSheet` (WB), `appendOzonSnapshot_` (`05_ozon.gs`), выгрузка МойСклад
    (`07_moysklad.gs`).
  - Лист ИП11 расширен вручную, недописанный блок 03.08 удалён и залит заново.
    04.08 восстановить нечем: WB отдаёт только снимок «сейчас», истории по дате нет.

### Известные ограничения
- Книга «Баланс Маркеты» — 6,9 млн ячеек из лимита в 10 млн. Автодобавление строк
  этот лимит приближает; чистить историю по-прежнему нужно вручную
  («Автоматизация → Сервис → Очистка данных»).

## [3.3.0] - 2026-08-04

### Fixed
- **ОСТАТКИ OZON БОЛЬШЕ НЕ ЗАТИРАЮТСЯ — каждый прогон стирал всю прошлую историю**
  (разбор владельца, 04.08.2026). `writeOzonSheet_` делал `sheet.clear()` перед
  записью, поэтому на листах «Остатки по кластерам ИПx» жил ровно один день —
  последний. Сравнить остатки с прошлой неделей было не по чему, хотя на листах WB
  (там пишет `writeToSheet`) история копилась месяцами.
  - `writeOzonSheet_` → `appendOzonSnapshot_` (`05_ozon.gs`): строки **дописываются**,
    дата прогона в колонке A, прошлые дни не трогаются.
  - Повторный прогон в тот же день не плодит дубли: `deleteRowsOfDay_` (`12_utils.gs`)
    сносит сегодняшний блок, и пишется свежий снимок. Побеждает последний прогон дня.
  - Лист старой раскладки (у ИП4 англоязычная шапка с датой в колонке I) не портится
    дописыванием 20 колонок: `ozonHeaderMatches_` ловит несовпадение, `archiveSheetCopy_`
    откладывает копию листа, и только после этого лист начинается заново.
  - Шапка закрепляется (`setFrozenRows(1)`) — истории теперь много.
- Восстановлены остатки Ozon за 03.08.2026 из ревизий Google Drive (ИП1 161 строка,
  ИП3 33, ИП6 17, ИП8 23, ИП9 6). Глубже 03.08 ревизии Drive уже подчищены — июль не вернуть.

### Известные ограничения
- Листы WB продолжают дублировать строки при двух прогонах за день (`writeToSheet`
  просто дописывает) — там справа стоят собственные колонки владельца с формулами,
  поэтому автоудаление сегодняшнего блока не включалось.
- Рост листов ограничивают вручную: «Автоматизация → Сервис → Очистка данных»
  (`cleanupOldData`, удаляет строки старше N дней на всех листах кабинетов и в логе).

## [3.2.0] - 2026-08-03

### Added
- **OZON: в отчёт попадает всё, что вверено маркетплейсу.** Старая ручка
  `/v2/analytics/stock_on_warehouses` показывает только физически лежащий товар —
  ни товаров в пути, ни возвратов, ни брака. Добавлен второй источник
  `/v1/analytics/stocks` (номенклатура для него собирается через
  `/v4/product/info/stocks`, запрос пачками по 100 SKU), источники склеиваются
  по «SKU + склад».
- Новые колонки листа (дописаны справа, первые 9 не тронуты — на них могут быть
  завязаны формулы соседних листов): `Доступно (аналитика)`, `В пути на склад`,
  `Заявлено к поставке`, `Возврат от покупателя`, `Возврат продавцу`,
  `Брак на складе`, `Брак в пути`, `Ждёт документов`, `Прочее`, `Кластер`,
  `Всего вверено OZON`.
- Замер на боевом кабинете: строк 819 → 1456, видимыми стали 3304 шт. в пути
  и 257 шт. возвратов, которых в отчёте не было вообще. `Заявлено к поставке`
  (ещё не отгруженная заявка) вынесено отдельной колонкой и в «Всего вверено» не входит.

### Fixed
- WB: `HTTP 204 No Content` на скачивании отчёта — это «остатков нет», а не сбой.
  `fetchWithRetry` считал успехом только 200, поэтому 204 уходил в три попытки и
  падал как «Адрес недоступен» (боевой случай ИП4). Теперь успех — любой 2xx.

## [3.1.0] - 2026-08-01

### Fixed
- **Остатки WB собираются заново.** WB отключил `statistics-api…/v1/supplier/stocks`
  20.07.2026 (заглушка `PLUG-404-20260720`, release-notes id=494) — сбор переведён на
  асинхронный отчёт «Остатки на складах» `seller-analytics-api…/v1/warehouse_remains`
  (заказ → статус → скачивание, боевой замер ~8 с на кабинет).
- `fetchWithRetry` больше не ретраит 4xx (кроме 429) и **кладёт в ошибку тело ответа**.
  Раньше в Telegram уходило «HTTP 404 (после 3 попыток)», хотя WB прямо в теле писал
  причину и ссылку на релиз-ноты; заодно 8 мёртвых кабинетов переставали жечь ~50 с
  из шестиминутного лимита GAS.
- 429 пережидается по заголовку `X-Ratelimit-Retry`, а не вслепую.
- `healthCheck()` проверял тот же отключённый URL и врал по всем WB-кабинетам —
  переведён на новую ручку; в текст отказа добавлено тело ответа.
- OZON: ответ с 0 строк больше не выглядит успехом. `writeOzonSheet_` на нуле строк
  выходил до `clearContents()`, лист оставался со вчерашними данными, а в отчёт шло
  «✅ +0» — теперь это явная ошибка кабинета.

### Changed
- Колонки `Цена` и `Скидка` на листах WB остаются пустыми: новый отчёт их не отдаёт.
  Раскладка листов не меняется, история не ломается.
- Псевдосклады отчёта: `В пути до получателей` и `В пути возвраты на склад WB`
  пишутся строками (как это делал старый API), `Всего находится на складах`
  пропускается — это сумма, она удвоила бы любой SUM по листу.

### Требуется от владельца кабинетов
- Новый отчёт живёт в разделе прав **«Аналитика»**. Токены, выпущенные только со
  «Статистикой», получают 401 `token scope not allowed` и требуют перевыпуска в ЛК:
  `seller.wildberries.ru/supplier-settings/access-to-api`.

## [3.0.0] - 2026-03-30

### Added
- Интеграция МойСклад: выгрузка остатков с себестоимостью в лист «Остатки МС»
- Поле API-токена МойСклад в Панели управления (B5)
- Модуль «Кредиты»: синхронизация остатков по кредитам в Управленческий баланс
- Мульти-чат Telegram (несколько chat_id через `;`)
- Дашборд с автообновлением и экспортом в CSV
- Разбивка монолита на модули (`src/00_constants.gs` … `src/99_menu.gs`)

### Changed
- Меню переименовано: «📦 Остатки МП и другие скрипты» → «Автоматизация»
- Подменю разделены на три независимых модуля: Остатки маркеты / Остатки МС / Кредиты
- `TABLE_START_ROW` сдвинут с 7 на 9 (добавлен блок МойСклад в строках 4-5)

### Security
- Удалены захардкоженные Telegram-токен и chat ID из функции миграции
